The default model is RPi-services/image-api/best_v11i_m.onnx (YOLOv8m-seg,

Speed 50, the 10 cm planner/tablet grid and 40 cm turn clearance are unchanged.

## After each scan

1. Algo tags SNAP commands with L/C/R camera alignment.
2. The Pi keeps Picamera2 open between scans, captures a photo and uploads it
   with its run, obstacle and attempt. rpicam-still remains the fallback.
3. CV saves an unannotated original locally before inference. It saves a result
   JSON for success, NA or inference error, and an annotated JPEG for success.
4. A successful result includes mdp_image_id (11–40) and target_obstacle_id.
   The legacy obstacle_id response field remains the numeric image ID.
5. The Pi validates/normalises the result, removes the obstacle from the failed
   list, caches its accepted image ID, and immediately queues TARGET,<obstacle>,<ID>.
6. Android stores the ID in BluetoothSession, updates the map and chat, and
   suppresses duplicate replay entries. Sending a fresh map clears previous IDs.

A photo by itself does not count as recognised. The current single-photo trial
takes one photo per visit without immediate recapture, with at most one revisit
pass (two photos maximum per revisited obstacle). Results from separate photos
are not compared or combined. Accepted obstacles stay as
physical obstacles in Algo collision checking and are not targeted on revisits.
The Pi can resend cached accepted IDs after a Bluetooth disconnect.

## Laptop files and access

All new ONNX capture evidence is in RPi-services/image-api/own_results/:

- *_original.jpg: every valid upload, including missed detections.
- *_annotated.jpg: the selected recognised target with a green bounding box
  and a green side panel showing the symbol and numeric image ID.
- *_result.json: IDs, confidence, run/obstacle/attempt and file URLs.
- stitched-<run hash>.jpg: montage generated by /stitch.

CV serves /results, /files/<filename>, and /stitch?run_id=<run ID> on port 8001.
Without run_id, /results and /stitch select the latest captured run. There is no
20-minute expiry for captures recorded by this version. Stitching retains one
latest successful capture per obstacle; repeated symbols do not overwrite other
obstacles. The JSON index survives server restarts. Pre-update annotated files
remain browsable and can be stitched when no new manifests exist.

Algo's existing /infer now forwards to CV, retaining its file upload field and
detections response. Algo /stitch also forwards to CV. Neither loads best.pt.
The CV model is warmed before startup health is exposed, avoiding cold-start
inference inside the Pi's first-photo timeout.

   ```bash
   cd /home/nat/SC2079-MDP/rpi
   ```
